# Аккаунты и данные «тише.»

## Опубликованный сайт

GitHub Pages — адаптивный сайт, а не приложение из App Store. Supabase Auth отправляет одноразовую ссылку на почту. После входа приложение загружает один документ `public.tishe_state` по идентификатору текущего пользователя. В документе находятся дела, привычки, настройки, заметки и разговоры. Фотографии хранятся отдельно в приватном bucket `tishe-photos` под путём `<user-id>/<photo-id>.jpg` и отображаются по краткоживущим подписанным ссылкам.

[SQL-схема](../supabase/schema.sql) включает RLS и разрешает читать и менять документ только своему `auth.uid()`. Для фотографий действуют отдельные правила на папку владельца. В браузер передаётся только публичный ключ Supabase. Секрет OpenAI хранится в Cloudflare Worker; Worker проверяет токен через Supabase перед запросом к модели и ограничивает частоту обращений по пользователю.

## Перенос и откат

Прежние записи из localStorage не отправляются на сервер автоматически. После первого входа пользователь выбирает «Перенести в аккаунт» или «Начать заново». Локальная копия удаляется только после подтверждённого сохранения документа. В настройках можно скачать JSON с фотографиями; при сбое записи приложение предлагает сделать копию и не позволяет выйти с несохранёнными изменениями. Старую версию кода можно восстановить из тега `before-supabase-storage` в локальном репозитории. Формат записей остаётся `version: 1`.

## Ограничения и проверка перед приглашением других

Сейчас весь пользовательский документ обновляется целиком. Ревизия предотвращает незаметную перезапись при одновременном редактировании на двух устройствах, но автоматического объединения изменений нет. Перед широким тестированием нужно войти двумя разными аккаунтами и проверить чтение, запись, удаление, экспорт, фотографии и выход. Также стоит проверить, что ссылки входа открываются на телефоне и компьютере, что при выключенной памяти её текст не отправляется ИИ, и что после удаления данных приватные фотографии недоступны.
